# 召回买不到：union 新增线的真线率 = F1/2（2026-09-13）

> 口径：冻结官方 Oracle 全局单次调用；尺子 = 15ep LVO OOF（7100 图，video-disjoint，G = 24435）。
> 本文回答一个问题：**别的模型独有而我们没有的线，加到预测里到底值不值？** 结论是不值，且原因不是"那些线不好"，而是它们的精度恰好等于评分公式自己的盈亏线。

## 0. 一句话结论

把另一棵 OOF 树（15ep、`cls_loss_weight=3.0`）里我们没检出的线并进来：

| 量 | 值 |
|---|---|
| 新增线 N | **789** |
| 其中真线 | **304.0** |
| 边际真线率 | **0.3853** |
| 盈亏线（= F1/2） | **0.3888** |
| F1 | 0.777628 → **0.777511**（**−0.012pp**） |

→ **union 既不加分也不减分，精确停在盈亏线上**（差 0.35 个百分点，ΔF1 只有 −0.012pp）。

## 1. 为什么"恰好等于盈亏线"不是巧合

全集池化 F1 = 2TP/(P+G)。加一条线：
- 真线 → ΔF1 = +2(FP+G)/(P+G)²
- 伪线 → ΔF1 = −2TP/(P+G)²

盈亏条件 `p·(FP+G) = (1−p)·TP`，解出 `p* = TP/(TP+FP+G)`。把 `TP = F1(P+G)/2` 代入：

```
p* = F1·(P+G)/2 / (P+G) = F1/2
```

**盈亏线恒等于 F1/2，与 P、G 的具体值无关。** 本次标尺 F1=0.7776 → p* = 0.3888，实测 0.3853。

本质含义：一个已经训练到收敛的检测器，**它"没检出来"的那部分候选，精度天然就在它自己的平均水准的一半附近** —— 那些线不是随机噪声（38.5% 是真线，远高于随机），但也正好不够本。想靠"多检一点"提分，必须把**边际精度本身**提上去，而不是增加条数。

## 2. 这条结论把哪些路封死了

| 路 | 状态 | 依据 |
|---|---|---|
| 降 conf 阈值多检 | 已封 | conf 0.30→0.50 加线的真线率只有 **23%**（远低于 36.75%） |
| **union（多模型并集）多检** | **已封（本文）** | 边际真线率 38.5% ≈ 盈亏线 38.9%，ΔF1 −0.012pp |
| 共识 / 融合 | 已封 | 先前两次干净 OOF 判负，与本文同机制 |
| 去重剪枝 | 已封 | testA 2664 条内互 IoU>0.5/0.7/0.85 的重复线**全为 0 条** |
| 底端裁剪（IoU 抬升） | **已开且已到顶** | 见 §3 |

→ **在 testA 上，FP 与 FN 都买不动了**：加线要 ≥36.75% 精度，union 给 38.5%（≈0）；删线要被删者 ≥63.2% 是伪线，conf 排序给不出这种区分度。

## 3. 唯一还活着的那条线：把已经检到的线抬过 IoU 门

testA 分解（G=3155.8）：TP 2138.9 / FP 525.1 / FN 1016.9，精确 0.803 / 召回 0.678。对 train OOF（0.816 / 0.743）而言**精确只差 1.3pp、召回差 6.5pp** —— 但召回差的成因不是"没检到"，很大一部分是**检到了但 IoU 没过 0.5**（一条检到却没过门的线同时贡献 1 FN + 1 FP）。

底端裁剪就是把这批线抬过门：

| 尺子 | 最优档位 | ΔF1 |
|---|---|---|
| 全量 OOF（train 几何） | gtcond+40 | **+4.224pp** |
| **testA 同几何子集**（12 clip / 1200 图，GT top 531–595） | **gtcond+0（cut≈712）** | **+0.099pp** |
| testA 实测（54ep） | gtcond+0 | **+0.069pp**（0.73505 → **0.73574**） |

同号同量级、且再深即崩（−10 → −0.93pp，−20 → −2.92pp）→ **trim 已在最优点，A 榜无进一步空间**。
