### 2.1 榜首反推（`P = F1·G/(2p − F1)`）

| 假设榜首精确率 | 推出 P | TP | 召回 |
|---|---|---|---|
| 0.95 | 2416 | 2295 | 0.727 |
| **0.90（P 与我们相同 2664）** | **2664** | **2397** | **0.760** |
| 0.85 | 2968 | 2523 | 0.799 |
| 0.80 | 3350 | 2680 | 0.849 |

**关键读数**：若榜首预测条数与我们相同（2664），其精确率 ≈ **0.90**、召回 ≈ **0.760**——**两项都优于我们**（0.804 / 0.678）。
→ 差距不是"少预测"，而是"每条预测更准 + 同时找到更多真线"。这才是真正的建模差距。

### 2.2 目标量化

在 **P 保持 2664 不变** 的前提下：

| 情景 | TP | F1 |
|---|---|---|
| 现状 | 2140.9 | 0.7357 |
| +200 真线 | 2340.9 | 0.8045 |
| **+257 真线 = 追平榜首** | **2397** | **0.8239** |

→ 追赶目标可写成一句可验证的话：**在不多预测的前提下，把 257 条"当前是 FP 或 FN"的线变成 TP。**

## N1. ⛔ 发 1 不要交 `union_trim0`：并集已用本地尺子判为"恰好盈亏"

已在诚实 OOF 上把 testA 的 union 构造**复现并打分**（`docs/union_true_rate_20260913.md`）：

| 量 | 值 |
|---|---|
| 新增线 N | 789 |
| 其中真线 | 304.0 |
| **边际真线率** | **0.3853** |
| **盈亏线 = F1/2** | **0.3888** |
| ΔF1 | **−0.012pp** |

**盈亏线恒等于 F1/2**（`p* = TP/(TP+FP+G)` 代入 `TP = F1(P+G)/2`），与 P/G 无关。实测 0.3853 vs 0.3888 → **并集精确中性，期望 0、方差也小**，不值得占一发。

补充：这也从机制上解释了"融合/共识判负"——**另一模型独有的线，其精度天然就在自身平均水准的一半附近**，union 抬不动召回。

## N3. 🔵 新配方已起跑（与 §6.3 不同，理由如下）

已发车：**`clrnet_r50_hires` = `1366×540 / cut180 / bs8`**（配置 `configs/unlanedet/clrnet_r50_hardlane_hires.py`，实例 HEAD `0c2fafa`）。

| | §6.3 的 cut400/h320 | 本次 1366×540 / cut180 |
|---|---|---|
| testA 路面带占输入行数 | 180 / 320 | **180 / 540**（比例 33%，但**绝对像素** 1.71x） |
| 各向同性 | ❌ 1.7:1（垂直拉伸） | ✅ **1:1**（基线 800×320 也是同性 0.586/0.593，故角度分布不变） |
| 横向分辨率 | 0.586（不变） | **1.0（提高 1.71x）** |
| 训练 GT 截断 | **24.3% 的线**（已量化） | **0%** |

**选它的理由**：官方门限是**横向**误差 <10.3px（原图坐标）——800 宽输入下只有 **6.0px** 余量，1366 宽下有 **10.3px**。召回缺口的成因被判为"检到但 IoU 未过门"，而 IoU 对横向误差最敏感，所以**横向分辨率**是比"路面带行数"更直接的杠杆；且不裁 GT、保持同性。

**已完成**（19:30 跑完 31932 iter）：`validate_run` 补跑后 **status=pass**，**best val F1 = 0.89680 @ iter 28383**（final 0.89646）——高于 54ep 的 0.89227、CLRerNet36 的 0.89087（val 对 all71 血统污染，只作训练内监控）。

**关键发现：hi-res 模型在同一 conf 下明显更保守**

| conf | 线数 | 空文件 |
|---|---|---|
| 0.50 | 2384 | 30 |
| 0.45 | 2480 | 20 |
| **0.40** | **2593** | **9** |
| （54ep @0.50 = A 榜 0.73574） | 2664 | 9 |

hi-res @0.50 比 54ep @0.50 少 10.5% 的线。由于 testA 的病根是**召回**（FN 是 FP 的 1.93 倍），拿一个"少报 10%"的模型去比是不公平的 —— 必须**对齐预测预算**后再比，这样才只隔离"分辨率"这一个变量。

→ **发 1 交 `submit_testA_hires_c40_trim0.zip`**（2593 线 / 9 空，与 2664 / 9 最接近，且已套 trim0）。备份 `submit_testA_hires_c45_trim0.zip`（2480 线）。两包均过 `prepare_submit` verify + 官方 `check_submission.py` 预检。
