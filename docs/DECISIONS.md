## 一、目标分数裁决：83.0 还是 84.0

两版 PRD 结论冲突。**裁决：双轨并行，两个数都留，不下调。**

| 视角 | 数值 | 方法 | 用途 |
|---|---|---|---|
| 竞争门槛（top-down） | **84.0** | 论文 SOTA 83.2 + 真增量 1.0 − 安全垫 0.2 | 决定"要不要做"某项投入（集成、分辨率 ablation、付费算力） |
| 能力预测（bottom-up） | **82.2**（中位，区间 80–84） | 复现 SOTA 80.6 + 真增量 1.6 | 决定"能不能做到"，用于风险沟通 |
| **执行缺口** | **1.8 pp** | — | 缺口必须靠**工程质量与迭代次数**补，不是靠调低目标 |

**为什么不按能力预测把目标下调到 82**：目标会自我实现。按能力定 82，就会砍掉集成、分辨率 ablation、付费算力这三项"补齐 1.8pp 缺口"的手段，然后真的停在 82。目标的作用是**拉伸执行**，不是描述预测。

**迭代纪律**：9/10 用 A 榜实际分布重估门槛；若观测门槛 >85 → 定位争前三，加大集成投入；若 <80 → 锚定稳进前 10，集中做可复现性。阶段性上限 86.0。

**常量收口声明（§14 制度）**：本节与 `configs/default.yaml`（`target:` 块）是目标常量的唯一定义处；其他文档（PRD/ARCHITECTURE/TASKS/overview）一律引用不得另设数值。

**当前值（2026-09-01 晚，§15.1 滚动重估首次触发后）**：工作性目标 **82.0**（保 80 冲 82）/ 冲刺线 **84.0** / 能力预测 **≈80.3**（区间 79.5–81.1）/ 缺口 **≈3.7pp**——取值已同步 `configs/default.yaml::target`。本节表格（84.0/82.2/1.8）为 α-SimADNet 链的原始裁决，保留作历史记录；重估规则与节点见 §15.1。此调整为**证据驱动**（UnLanedet 无 RVLD/α-SimADNet + 同框架复现分数），手段未减（增强/分辨率/后处理/预算全保留），区别于本节反对的预判式下调。

## 二、算力测算修正（我上一轮的数字是错的）

许清楚指出 4090 相对 **T4 单卡**约 3~4×（算力 2.5×、带宽 3.1×），而 T4×2 相对 T4 单卡已加成 1.7×，故 **4090 / T4×2 ≈ 1.8~2.4×，取 2.0× 保守**。我上一轮用的 3.2× 是错的。

| 项目 | 我上一轮（3.2×） | **修正后（2.0×）** |
|---|---|---|
| 4090 吞吐 | 7.65 图/秒 | **4.78 图/秒** |
| 1 epoch | 14.2 分钟 | **22.7 分钟** |
| 36 ep 纯训练 | 8.5 h | **13.6 h** |
| **一次完整实验（含冗余）** | 14.3 h | **20.9 h ≈ 一整天** |
| 172 元能买几次完整实验 | 6.2 次 | **3.3 次** |
| 单次完整实验成本 | 36 元 | **52 元** |

**结论修正**：
1. ~~"约 172 元把实验次数从 1 次拉到 6 次"~~ → **从 1.9 次拉到 3.3 次**（Kaggle 69h 能跑 1.9 次）

3. 付费算力的价值主张不变（仍是 3 倍实验次数），但**绝对次数比我说的一半还少**，排期必须按 21h/次重排

⚠️ 上述仍为测算值，T4 折扣系数 0.55 未实测校准。首个 GPU session 必须实测 1 epoch 耗时并重算全表。

## 四、输入分辨率：本赛题最被低估的隐性天花板

许清楚给出了比我更精确的论证：

- 800 宽缩放系数 0.586 → **模型在 800 宽上差 1px = 原图 1.71px**
- 高度压到 320，纵向步长 = 720/320 = **2.25 px/行** → 端点纵向定位天然有 ±1.1px 量化误差
- F1@0.7 对应容差 `d = 5.3px`，在 800 宽下只剩 **3.1px**，已接近量化步长量级

**这很可能就是论文 F1@0.7 从 83.2 断崖到 60.9 的原因之一**——不是模型不会定位，而是**坐标系把精度压没了**。

**排期建议**：优先级排在**零成本后处理之后、CLAHE 之前**。

## 六、跨帧时序：不做，且不问

两版 PRD 原本都建议"若收益 ≥2pp 则向组委会书面确认"。**许清楚撤回了这条，我采纳。**

理由：
1. 【测算】1 秒间隔 × 60km/h → 相邻帧车辆位移约 **16.7 米**，场景已实质变化，时序平滑的先验失效，预期收益 **<1pp**
2. 收益 <1pp 意味着"≥2pp 才去问"的触发条件**永远不会被满足**，这条建议是空转的
3. **主动询问反而会让组委会记住这支队伍**——在无实质收益的情况下增加被关注风险，不划算

**决定：完全单帧检测，不实现、不询问、不保留开关。**

## 九、F1 恒等式与操作判据（脚本实测，非估算）

**背景**：v2 PRD 声称"每图平均多/漏 0.1 条线 ≈ F1 掉 1.0pp"。许清楚要求交叉验证。
**做法**：以 SOTA 工作点（G=4000 真值线、TP=3280、P=3882）为基准做数值实验。

```
== 验证恒等式 F1 = 2*TP/(P+G) ==
  常规算法: Prec=0.8449 Rec=0.8200 -> F1=0.8323
  恒等式  : 2*TP/(P+G) = 0.8323   一致

== 验证 v2 的"每图多/漏 0.1 条线 ≈ F1 掉 1.0pp" ==
  多画100条线 F1 = 0.8218  -> Δ = -1.04 pp
  少画100条线 F1 = 0.8430  -> Δ = +1.07 pp        ✅ v2 的表述成立

== 关键：两种操作的边际收益不对称 ==
  多检对 1 条线      : +0.0254 pp
  少画 1 条废线      : +0.0106 pp
  比值              : 2.40 倍  -> 检对比抑制 FP 更值钱

== 操作判据：放宽阈值什么时候划算？ ==
  新增预测线的匹配率必须 > TP/(P+G) = F1/2 = 41.6%
    新线匹配率 40%（增100条,匹配40条）: ΔF1 = -0.041 pp  亏
    新线匹配率 42%（增100条,匹配42条）: ΔF1 = +0.010 pp  划算

== 从 83.2 冲 84.0 需要什么 ==
  多检对 24条 / 预测线减少 18条 -> F1 = 0.8403  达标
  多检对 40条 / 预测线增加  0条 -> F1 = 0.8424  达标
  多检对  0条 / 预测线减少 40条 -> F1 = 0.8365  不达标
```

**四条可直接执行的判据（J1–J3 本次新增；J4 二轮审计新增）**

| # | 判据 | 用途 |
|---|---|---|
| J1 | `F1 = 2·TP/(P+G)`。调试时**只需要盯 TP 和 P 两个数**，不必反复算 P/R 再合成 F1 | 日报/台账的字段设计 |
| J2 | **放宽置信度阈值的充要条件**：新增预测线的匹配率 > `F1/2`（当前 ≈41.6%）。低于此值，阈值扫到再低也是净亏 | `scripts/sweep_threshold.py` 的停止条件，不用等到跑完整个网格 |
| J3 | **检对的边际价值是抑制 FP 的 2.40 倍**。当两个改动互斥、只能做一个时，优先做能提升召回的那个；`max_lanes` 截断要保守（宁可多留 1 条等 NMS，也不要在阈值层砍掉） | 后处理链 `order` 与 `max_lanes` 默认值 |
| J4 | **阈值网格扫描（T51）的采纳条件**（§15.3）：① 取「平台区」中心而非单点峰值——在峰值收益 ≥98% 的连续参数区间内取稳健点；② 扫描全表入台账（含负结果）；③ 最终组合必须在**段级 bootstrap CI 下界**上赢基线 ≥2.0pp（均值赢不算数） | 8 段 val 上几十组网格取最优 = 多重比较过拟合，与 A 榜过拟合（R3）同病；J4 把防过拟合纪律推广到 val 网格 |

J3 与 §3 的结论（真增量只有 +1.6pp）叠加后的推论：**"少画 18 条废线"这条路的 0.15pp 天花板很低，
84.0 主要得靠"多检对 24~40 条"**，也就是靠恶劣场景下的召回——退化增强（T4.3）与分辨率（D6）是主战场，
后处理阈值只是收尾。这条改变了 W3/W4 的权重：**W4（增强/配方）的重要性高于 W3（后处理）**。

### 9.1 metric 复刻实测结论（T11/T12 · 2026-09-01 落盘）

本地 metric 模块已实现并自检全绿（`tests/test_metric_selfcheck.py`，8 项全过）。
核心实现：`src/eval/rasterize.py`（B 样条 k=3 稠密化 + `cv2.polylines(thickness=30, lineType=8)`）
→ `src/eval/matching.py`（逐图 IoU 矩阵 + Hungarian 一对一指派 + IoU>0.5 判 TP）→
`F1 = 2·TP/(P+G)`。所有栅格参数（canvas/line_width/line_type/spline_k/densify_step）全部可配。

**关键校正（影响 §9 顶部的"10px 横向误差边界"表述）**：
- 理想矩形模型 `IoU=(30−d)/(30+d)` 在 d=10px 时给 IoU=0.5；
- 但 **cv2 的 `thickness=30` 描边有效宽度≈31px**，实测 `IoU(10px)=0.5122`（而非 0.5000）。
- 因此真实的 IoU=0.5 边界是 **≈10.3px**，不是精确 10px。10px 偏移仍判 TP，11px 才判 FN。
- 该偏差与官方一致（官方同用 cv2），属**忠实复刻**；0.3px 偏移远在 2pp 决策容差内，不影响任何 J1–J3 判据。
- 实测对照：`IoU(5px)=0.7222`（理想 0.7143）、`IoU(15px)=0.3478`（理想 0.3333），均 <0.02 容差。

**结论**：测量仪器可靠，后续基线/消融的 F1 读数可直接采信，无需 A 榜反演标定（Q-A3 关闭）。
下一步按 §6.5 单人关键路径推进 T20 三格式解析 → T21 一致性 → T22 EDA。

## 十、架构文档 GPU 口径复核（2026-09-01）

高见远交付 `ARCHITECTURE.md` 后，我用脚本把它的 GPU 需求（§6 任务表）与 §2 的供给口径对齐。

```
【需求】ARCHITECTURE.md §6 全部 GPU 项
  训练总 epoch 数            162 ep   (T2.4 15 + T2.5 30 + T2.6 36 + T4.3 45 + T4.5 36)

【缺口】先用满 Kaggle 免费额度，再买 4090
  Kaggle 吸收                68.5 T4x2-h  ≡ 34.2 4090-h
  仍需 4090                  26.8 h
    @2.5 元/h  ->      67 元
    @3.0 元/h  ->      80 元

【反推】预算 → 可做的 36ep 完整实验次数（一次 = 12.5 4090-h）
  预算   0 元 -> 总 34.2 4090-h当量 = 需求的  56.1%  ≈  2.7 次
  预算 100 元 -> 总 74.2 4090-h当量 = 需求的 121.7%  ≈  5.9 次

  预算 300 元 -> 总154.2 4090-h当量 = 需求的 252.9%  ≈ 12.3 次
```

**三条结论**

1. **这个赛题的算力不是瓶颈。** 架构文档全部 GPU 需求用满 Kaggle 后只需补 **67~80 元**。
   我上一轮说"172 元买 3.3 次完整实验"是按"全部任务都在 4090 上跑"算的，没有先把 Kaggle 免费额度用满——那是错的口径。
   **修正后：预算 100 元即可覆盖全部计划（含 2 折交叉确认），200 元有约一倍的容错冗余。**
2. **真正的瓶颈是人工，不是钱。** 用满 68.5h Kaggle 需要 **7.6 个 9 小时 session**，
   每个都要 Save & Run All 并在中途巡检（60 分钟无操作会断连）。按每天 2 个 session 算约 **3.8 个整天** 被训练占住。
   而人工总工时 W0–W6 约 139h。**人力才是稀缺资源，这也直接决定 Q2（队伍规模）比 Q1（预算）更该先定。**
3. **因此 §8 里 Q1 的排序要下调。** 预算 100 元就够，Q1 从"决定 1.8pp 缺口能不能补"降为"确认性支出"；
   真正决定成败的是 **Q2（有几个人、每周多少小时）** 和 **Q6（能否出席答辩）**。

## 十三、单人约束下的范围裁剪（关键）

**问题**：架构文档 §6.2 全表人工 ≈ **320h**（其中 W0–W6 ≈ **139h**）。单人 16 天窗口（9/1–9/17）= **8.7h/天**，且需同时 babysit 7.6 个 Kaggle 9h session（每个 Save & Run All + 巡检）。原架构的"三线并行"指 **CPU 任务（评测/数据/后处理）在 Mac 上跑、GPU 训练后台提交**——单人在机制上可行，但**纯人工编码量仍远超单人容量**。原 45 任务计划对单人不可行，必须砍。

**核心判断**：单人下 **GPU 不是瓶颈（200 元 ≈ 9 次实验足够），人工才是**。真正决定能否进前三的是"能否在 16 天内把 baseline→后处理→分辨率→1 组增强 这 4 步高质量跑完并冻结"，而不是实验次数多少。

### 15.2 预训练权重策略（修复「缺公开预训练权重」）
