## 1. 数据集与切分

- 总 **90 段真实行车视频 → 9000 张图**（每段以 30× 帧率下采样均匀抽 100 帧）。
- 训练集：**71 段 / 7100 张**，含原始图 + 三格式真值（TXT、JSON、单通道 instance PNG：0=背景，非零=实例编号）；附 `db_info.yaml` 索引。
- 测试集 A：**9 段 / 900 张**（日常榜，不计入最终成绩）。
- 测试集 B：**10 段 / 1000 张**（最终排名，末期发布）。
- **视频级严格隔离**：训练集与测试集以"原始视频"为单位划分，同一视频的图像绝不跨子集。→ 印证本项目 LVO 泄漏诊断与全量 71 段训练决策。
- 车道线编号：以图像中心为参照，左右交替编号（左侧最近=1，右侧最近=2，向外递增）。

## 2. 评测指标（F1 唯一核心标准）

- 画布 **1366×720**；B 样条插值（阶数 k≤3）稠密化采样；线宽**严格 30px，无抗锯齿**，单通道布尔值。
- 匈牙利算法求预测集×真值集 IoU 矩阵的一对一最优匹配；匹配及格条件 **IoU > 0.5**。
- TP = 匹配成功且 IoU>0.5 的预测线；FP = 图内总预测线 − TP（含未匹配、匹配但 IoU≤0.5、重复预测）；FN = 图内总真值线 − TP。
- A、B **各自独立**全局累加 TP/FP/FN → 各自算 F1，**不合并**。
- → 印证本地 metric 复刻（thickness=30，IoU=0.5≈10.3px 边界，F1 恒等式）；Oracle 证伪推理端有效。

## 3. 提交格式

### 3.1 submit.zip（预测结果包，每日提交用）

- **文件大小：< 200MB**（官方规则四.4，明确归属预测包）。
- 解压后**必须含 `submit/` 根文件夹**，子目录结构严格对应测试集，后缀 `.lines.txt`。
  - testA：9 段子文件夹 / 900 个 `.lines.txt`，`testA.txt` 校验。
  - testB：10 段子文件夹 / 1000 个 `.lines.txt`，`testB.txt` 校验。
- 空检测也必须提交**内容为空的** `.lines.txt`；缺失/多余/路径错误 → **整包无效**。
- 坐标系：左上原点 (0,0)，x 向右 / y 向下；基于 **1366×720 的绝对像素**浮点，**保留 1 位小数**；严禁 [0,1] 归一化、NaN/Inf；越界截断到边界。
- 每行一条车道线实例，空格分隔 `x1 y1 x2 y2 ...`，单行数值个数**为偶数**，至少 **2 个关键点（≥4 个数）**。
- 路径示例：testA 图 `v271974723_1_0_1925/00000.jpg` → `submit/v271974723_1_0_1925/00000.lines.txt`。

### 3.2 solution.zip（复现包，前三硬门槛）

- B 榜发布前冻结，须含**完整代码 + 权重 + 配置 + 依赖说明**。
- 提交**完整 64 位 SHA-256 + 精确字节数**。
- 测试集 B 结束后，前三名上传**字节完全一致**的压缩包；无法复现则取消排名顺延。
- 详见 §6 体积裁决。

## 6. D6/Q6 体积裁决（2026-09-08 核对结论）

> 关联：`docs/PRD.md` 开放问题 Q6、`docs/top3_sprint_plan_20260908.md` §10 D6、`docs/attack_top3_plan_20260908.md` §B4。

- **官方规则未对 solution.zip 设显式 MB 上限**。官方页"文件大小：<200MB"位于预测格式条款（四.1–四.3）之后、solution.zip 条款（四.5）之前，**字面归属 submit.zip（预测包）**。
- 因此 solution.zip 仅受"完整代码+权重+配置+依赖说明 + 64 位 SHA-256 字节一致"约束：**多权重集成（ensemble）与 Soup 单模型均可提交，不被官方体积强制**。
- **权重必须内嵌**：官方要求 solution.zip 含"完整代码、权重、配置和依赖说明"——不允许"代码 + 权重下载链接"。
- 本项目 `docs/PRD.md` P1-C21 的"权重 FP16 后 solution 包体 <200MB"与 R13"包体超 200MB"风险项是**团队自设工程纪律**，非官方规则；继续按此纪律执行（ensemble 走 FP16），但不构成对官方体积的硬约束。
- **对 T2 的含义**：原"体积决定 Soup 单模型 vs 多权重集成"的前提**不成立** → T2 可追求期望更高的 ensemble，Soup 作为兜底；二者均以 FP16 权重满足自设 <200MB 纪律。
- 非阻塞待办：可发函组委会 `AICompetition@iflytek.com` 二次确认平台是否另有隐性上传上限（不影响当前架构决策）。
