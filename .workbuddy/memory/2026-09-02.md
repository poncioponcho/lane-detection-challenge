用户 rsync 用 `root@i-2ae168353e00101db8` 报 `Could not resolve hostname`。根因：`I2ae168353e00101db8` 是**容器内 shell prompt 的主机名**（登录后可见），不是外部可达的 SSH 地址。真实端点在恒源云控制台（host + 端口），或 Mac `history | grep ssh`；首次登录贴的是 `root@i-1.gpushare.com`（候选）。

语法坑：rsync 非标端口走 `-e "ssh -p <PORT>"`，**不是** `-P`（`-P` 在 rsync = `--partial --progress`）；scp 才用 `-P <PORT>`。修正：`rsync -azP -e "ssh -p <PORT>" <src> root@<SSH_HOST>:/hy-tmp/...` 与 `scp -P <PORT> /tmp/lane-challenge.bundle root@<SSH_HOST>:/hy-tmp/`。先 `ssh -p <PORT> root@<SSH_HOST>` 通了再传大文件。

**恒源云实例默认无 rsync**（`bash: rsync: command not found`）。传输改走：`tar cf - -C <srcdir> . | ssh -p <PORT> root@<HOST> "mkdir -p <dst> && tar xf - -C <dst>"`（媒体已压缩不必 -z），或 `scp -P <PORT> -r <src>/. <HOST>:<dst>/`，或一次性 `apt-get install -y rsync`。**已确认可达端点：host=`i-1.gpushare.com`、端口=`34529`**（ssh 可进）。

**macOS tar→Linux 刷 `LIBARCHIVE.xattr.com.apple.quarantine` 警告**：macOS 给下载文件打的 quarantine xattr，远端 GNU tar 不认，逐文件刷 `Ignoring unknown extended header keyword`，**无害、文件照传**。传输中勿中断（tar|ssh 不可续传）；传完用两端 `find <dir> -type f | wc -l` 对账。消除：源端 `COPYFILE_DISABLE=1 tar --no-xattrs cf - -C <src> . | ssh ...
